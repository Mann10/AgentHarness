# Phase 260806-v10: TUI Queue Panel for Backlogged Prompts Summary

**Scheduler FIFO backlog surfaced to the TUI as a bordered "Queue" panel above the input bar via a new `backlog_changed` RPC notification — driven by a parallel deque mirror for queue-head peek, emitting on enqueue/drain/cancel, with the panel hiding at depth 0.**

## Accomplishments
- `BacklogChangedEvent` dataclass + `EVENT_BACKLOG_CHANGED` constant; Scheduler now publishes current `{depth, next_prompt}` after every backlog mutation (enqueue in `submit_prompt`, drain before spawning the next turn in `_run_turn`, and cancel which clears the backlog and emits depth=0 unconditionally).
- `_backlog_mirror: deque[str]` parallel to the asyncio.Queue for FIFO-head peek — `asyncio.Queue` cannot peek, so the TUI gets the next queued prompt text; mirror mutations are synchronous-adjacent to queue mutations (no await between) so the mirror never drifts.
- `backlog_changed` threaded through all four layers: `NotificationType.backlog_changed`, `_DOMAIN_TO_NOTIFICATION` + `_PAYLOAD_EXTRACTORS` registration, bus subscribe/unsubscribe in `start()`/`shutdown()`, typed `BacklogChangedPayload` + `AgentState.queue` slice with `setBacklog` action and session-switch reset.
- New `QueuePanel` component (bordered, gray, informational) rendering the truncated quoted head prompt with `(+N more waiting)` where N = depth − 1; returns `null` when depth === 0.
- 7 new focused tests: 4 emission tests (enqueue depth/head, drain-to-zero, cancel-clears) + 2 exact wire-format tests + 1 end-to-end Scheduler→EventBus→RPCServer→NDJSON forwarding test.

## Decisions Made
- **Cancel clears the backlog (D-v10 documented decision):** queued prompts under a cancelled turn never execute (the drain never runs on a cancelled task). `cancel()` now empties the queue + mirror and emits depth=0 unconditionally — the panel can never display prompts that will not execute (threat T-260806-04).
- **Payload contract `{depth, next_prompt}` ONLY:** session_id rides on the notification request_id, matching the `skill_loaded` precedent (D-06 style). No session_id duplication in the payload.
- **Panel copy:** body is `"<prompt>" (+N more waiting)` with N = depth − 1; the LOCKED `QUEUE:` prefix from the user's inline example is redundant inside a titled panel (design decision 7 in the plan).
- **Session switch reset (WR-05):** `setActiveSession` resets `queue` to `{depth: 0, nextPrompt: ""}` and the client case guards on `params.request_id === state.activeSessionId`.
