<objective>
Close the H-01 blocking gap: the D-07/ACT-02 "exactly once" dedup contract is broken for case-variant re-loads on the primary win32 platform.

Purpose: `RuntimeAPI.load_skill` dedups by comparing the raw caller name (`e["name"] == name`, `harness/runtime.py:189`) while `SkillStore.lookup()` keys case-insensitively on win32 (`os.name == 'nt'`, `skills/store.py:32-37`). Loading `demo-greeter` then `DEMO-GREETER` passes the dedup check, injects the skill body as a system message TWICE, and appends TWO `skill_state["loaded"]` records — empirically reproduced on this machine (body_count=2, 2 records). This violates ROADMAP SC1 ("exactly once"), D-07 (no-op re-load), and ACT-02 (exactly-once auto-invoke), and inflates every subsequent LLM call with a duplicate instruction block.

Output: Fixed `load_skill` dedup (canonical-name comparison + mark-before-inject) and two regression tests (unit + E2E) that fail on the pre-fix code and pass after — closing the identical-string-only blind spot that kept the suite green.
</objective>
