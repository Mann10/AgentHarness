   async def load_skill_status(self, name: str) -> dict:
       """D-06: structured load result — {skill: <canonical>, status: loaded|already_loaded}.

       No body echoed. KeyError propagates for unknown skills (adapter maps to

           raise RuntimeError("SkillStore not configured")

           raise RuntimeError("No active session")

       await self.load_skill(info.name)                   # D-07 shared path
       return {"skill": info.name, "status": "loaded"}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RPC client → Dispatcher | Untrusted NDJSON requests cross from the TUI/remote subprocess into the dispatcher registry (whitelisted method names only) |
| Dispatcher → RPCAdapter → RuntimeAPI | Params dict crosses into the adapter; adapter must validate before touching runtime state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Spoofing | Dispatcher.dispatch | mitigate | Method names constrained by the RPC_METHODS whitelist + Dispatcher registry — only registered handlers run; "skills.load" must be registered in register_all() |
| T-15-02 | Tampering | handle_skills_load params | mitigate | Validate `params["name"]` is a non-empty str before use (raises INVALID_PARAMS, D-08); name never interpolated into paths — SkillStore.lookup() guards traversal |
| T-15-03 | Info Disclosure | skills.load response | mitigate | D-06: response returns {skill, status} only — skill body is never echoed (same no-body contract as read_skill D-05) |
| T-15-04 | DoS | handle_skills_load → load_skill | mitigate | Unknown-skill loads rejected fast (-32001) with no state change; actual loads bounded by the loaded-skill token cap (Plan 15-03) and exactly-once dedup (H-01) — repeated loads are no-ops |
| T-15-05 | Tampering | Dispatcher error wrapping | mitigate | RPCError passthrough returns the handler's own code/message; generic exceptions still wrapped as -32603 so no stack details leak to the client |
</threat_model>
