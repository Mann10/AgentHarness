## Conventions the plans encode

1. **Package layout:** `skills/__init__.py` re-exports public API via explicit `__all__` (CONVENTIONS "Barrel Files"); consumers import `from skills import SkillInfo, discover_skills, build_manifest_text` — not from submodules.
2. **Dataclasses:** `SkillInfo` frozen dataclass (immutable — safe to hold across discovery → manifest). Type annotations on everything; `from __future__ import annotations` first line.
3. **Error taxonomy:** skip-and-warn mirrors `session/store.py` corrupt-JSONL handling: catch `yaml.YAMLError`, `UnicodeDecodeError`, `OSError`, `TypeError`/`ValueError` per skill; `logger.warning(...)`; never raise out of the discovery path (P-07, D-03). No new exception classes needed — `None` return is the contract (`SkillInfo | None`).
4. **Logging:** module-level `logger = logging.getLogger(__name__)`; `logger.warning` for skip/shadow/trim/mismatch; warning text must name the offending file/skill (authors must know what to fix).
5. **Determinism:** all iteration order derives from `sorted(...)` — first-wins dedupe (D-04), manifest line order (D-11), trim selection (D-10) all share one normalized-name sort.
6. **Windows awareness:** win32 case-insensitive name match (D-06) via `os.name == "nt"` or `sys.platform == "win32"`; CRLF-safe frontmatter splitter (STACK pattern handles `\r\n`).
7. **Test style:** `@pytest.mark.asyncio` only where async; skills code is synchronous (discovery/manifest are pure + sync — no `asyncio.to_thread` needed at this scale per CONTEXT code_context); `tmp_path` fixtures for temp skills dirs.

## Anti-patterns to avoid (from research)

- Re-scan per LLM call without cache — allowed at this scale (O(dirs), D-08 per-call rebuild is the locked decision), but discovery must stay a cheap `os.scandir`/`Path.iterdir()` — no re-parsing framework, no watcher.
- `yaml.load` / `eval` on frontmatter — `yaml.safe_load` only (T-12-01, P-07).
- Dropping whole skills when over budget — D-10: descriptions trim, skills stay listed.
- Mutating `Session` serialization — `to_snapshot_meta()`/`from_events()` untouched; `skill_manifest` is a plain defaulted dataclass field.
