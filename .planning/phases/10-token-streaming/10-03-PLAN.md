  ```tsx
  </Box>
  ```

  WHY THIS ORDER (column-reverse semantics): the FIRST child in DOM renders at the BOTTOM. DOM order = [thinking indicators, newest message, ..., oldest message] → visual top-to-bottom = oldest → ... → newest → indicator. When content exceeds the bounded panel height, overflow clips at the TOP, so the newest streamed content and the thinking indicator always stay visible. With few messages, content anchors to the bottom (chat-app convention) — that is intended, do not "fix" it.

  Changes from current code: (1) `flexDirection="column"` → `flexDirection="column-reverse"`, (2) `flexGrow={1}` added so the list fills the bordered panel height and anchors to the bottom, (3) both thinking-indicator blocks moved to be the FIRST children (before the mapped messages), (4) `conversation.map` → `[...conversation].reverse().map`.

  The empty-state hint (`Type a message to start a conversation`) stays where it is — a sibling rendered before this Box; when conversation is empty nothing else renders so it is visible.
