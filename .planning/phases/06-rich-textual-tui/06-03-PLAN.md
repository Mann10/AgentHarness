## Tasks

### 1. Build SessionPicker Screen

**File:** `tui/screens/session_picker.py`

**Screen:** Modal overlay (semi-transparent background, centered dialog).

**Content:**
```
┌───────────── Sessions ─────────────┐
│ ○  Untitled             12 msgs  2h│
│ ●  Debug Session         5 msgs 30m│  ← active
│ ○  Feature Planning     24 msgs  1d│
│                                    │
│ n: new   r: rename   d: delete     │
└────────────────────────────────────┘
```

**Implementation:** Use a `VerticalScroll` with a list of `Static` rows inside a `Vertical` container with border.

**Actions:**
- `Enter` / click: Resume selected session (calls `runtime.switch_session(id)`), then dismisses screen and updates conversation (calls `ConversationView.clear()`)
- `n`: Create new session (calls `runtime._session_manager.create_session(...)`, dismisses)
- `r`: Rename — shows inline input prompt, then updates session title
- `d`: Delete — shows confirmation, then calls `runtime._session_manager.store.delete(id)`, refreshes list
- `Esc`: Dismiss

**Triggers:** Bound to a keybinding (e.g., `ctrl+s`) in `app.py` or accessible via `/sessions` command in InputBar.

### 3. Manual testing and polish

Test the full flow:
1. Launch `python main.py --tui`
2. Type a prompt → ConversationView shows user message, agent response with markdown
3. Agent makes tool calls → ToolCallCards appear collapsed, expand on click
4. Jobs appear in sidebar with status dots
5. ToolTimeline shows chips during processing, clears on completion
6. StatusBar shows spinner, token count, session name
7. `/sessions` command opens SessionPicker
8. Create/resume/rename/delete sessions works
9. Ctrl+C exits cleanly

Edge cases:
- Long agent responses (2000+ chars) — markdown rendering performance
- Multiple rapid tool calls (5+) — ToolCallCards stack correctly
- Error handling — ErrorEvent renders red cards
- Empty state — No messages shows empty conversation, empty sidebar shows "No jobs"
- Session switch — clears conversation, loads new session context
