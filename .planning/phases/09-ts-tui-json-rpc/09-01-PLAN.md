<objective>
Build the JSON-RPC 2.0 adapter layer for the Python backend. This creates `backend/rpc/` module with protocol schemas, dispatcher, RuntimeAPI adapter, stdio server, adds `TokenProduced` event to harness/events.py, `create_session`/`delete_session` to RuntimeAPI, and wires the `--rpc` CLI flag into main.py.

Purpose: The RPC adapter is the foundation of Phase 9 — it enables the TypeScript TUI to communicate with the existing Python RuntimeAPI over stdin/stdout JSON-RPC 2.0 without modifying RuntimeAPI or EventBus internals.

Output: A working `backend/rpc/` module and `--rpc` entry point that handles all 7 RPC methods (chat, cancel, sessions.*, ping) and streams typed EventBus events as JSON-RPC notifications.
</objective>

  1. Create `backend/rpc/server.py`:

  **`class RPCServer`:**
  - Constructor takes `runtime: RuntimeAPI`
  - Creates `Dispatcher` and `RPCAdapter`, calls `adapter.register_all(dispatcher)`
  - Stores `self._runtime`, `self._dispatcher`, `self._adapter`
  - `self._running: bool = False`

  **`async def start(self)`:**
  - Set `self._running = True`
  - Subscribe to ALL EventBus events (TurnStarted, ToolCallEvent, ToolResultEvent, TokenProduced, ResponseComplete, CancelledEvent, ErrorEvent) using the event type constants
  - The event handler callback converts each event to a `RPCNotification` with the NDJSON format per D-08:
    ```python
    {"jsonrpc": "2.0", "method": "event", "params": {"type": "<notification_type>", "request_id": "...", "payload": {...}}}
    ```
    Where notification_type maps per D-09:
    - TurnStarted → "turn_started"
    - ToolCallEvent → "tool_call"
    - ToolResultEvent → "tool_result"
    - TokenProduced → "token"
    - ResponseComplete → "response_complete"
    - CancelledEvent → "cancelled"
    - ErrorEvent → "error"
  - The callback writes the NDJSON line to stdout and flushes: `sys.stdout.write(json.dumps(msg) + "\n"); sys.stdout.flush()`
  - Start the read loop task: `self._read_task = asyncio.create_task(self._read_loop())`
  - Note: use `sys.stdout` directly (NOT `print()`) and always flush

  **`async def _read_loop(self)`:**
  - Read from `sys.stdin` line by line using `asyncio.to_thread(sys.stdin.readline)`
  - Parse each line as JSON → validate as `RPCRequest`
  - Pass to `self._dispatcher.dispatch(request)`
  - Write response as NDJSON to stdout: `sys.stdout.write(json.dumps(response) + "\n"); sys.stdout.flush()`
  - On JSON parse error: write standardized -32700 error response
  - On EOF (stdin closed): set `self._running = False`

  **`async def shutdown(self)`:**
  - Unsubscribe all event listeners
  - Cancel read loop task
  - Flush stdout

  **Event-to-payload conversion helpers:**
  - Create a private method `_event_to_notification(self, event_type: str, event: HarnessEvent) -> RPCNotification` that:
    - Maps domain event type to notification type string using a dict constant
    - Extracts relevant fields from each event type into a dict payload
    - For `request_id`: use `event.session_id` or `event.event_id` as fallback
    - Returns the notification object ready for serialization

  **Event payload extraction rules:**
  - TurnStarted: `{"session_id", "prompt"}`
  - ToolCallEvent: `{"session_id", "tool_name", "arguments", "tool_call_id"}`
  - ToolResultEvent: `{"session_id", "tool_name", "result", "tool_call_id"}`
  - TokenProduced: `{"session_id", "chunk", "request_id"}`
  - ResponseComplete: `{"session_id", "content", "iterations", "tool_calls_made", "forced"}`
  - CancelledEvent: `{"session_id"}`
  - ErrorEvent: `{"session_id", "error"}`

  ```python
  async def run_rpc(config: Config, client: OpenAIClient, registry: ToolRegistry) -> None:
      """Start RuntimeAPI and enter JSON-RPC server mode over stdin/stdout.
      
      RPC mode is designed for the TypeScript TUI subprocess workflow (D-16, D-17).
      All output must be NDJSON on stdout — stderr for logging only.
      """
      runtime = RuntimeAPI(config, client, registry)
      await runtime.start()
      
      from backend.rpc.server import RPCServer
      server = RPCServer(runtime)
      
      try:
          await server.start()
          # Keep running until stdin closes or shutdown is requested
          while server._running:
              await asyncio.sleep(1.0)
      finally:
          await server.shutdown()
          await runtime.shutdown()
  ```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Spoofing | stdin input | accept | Local IPC only — no network exposure. The TUI is the only consumer and is trusted within the same user session. |
| T-09-02 | Tampering | stdin buffer | mitigate | JSON-RPC parser rejects malformed JSON with -32700 parse error. Dispatcher validates params type is dict where expected. |
| T-09-03 | DoS | stdin loop | accept | Unbounded input processing is acceptable for a local CLI tool. The user controls what the TUI sends, and can terminate the process. |
| T-09-04 | Info Disclosure | stdout events | accept | Event payloads contain session data but only flow to the local TUI subprocess on the same machine. No network transport. |
</threat_model>
