# Phase 11 — Session Popup & Panel Layout: UI Design Contract

> Visual and interaction contract for the Ink TUI (`tui-ink/`) changes in Phase 11.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **This is a TERMINAL UI (Ink 7.1 + React 19).** All units are **character cells**, not px. There is no font-size control, no line-height beyond 1, and no CSS. Styling is exclusively Ink props on `<Box>`/`<Text>` (`color`, `bold`, `dimColor`, `italic`, `underline`, `reverse`, `borderStyle`, `borderColor`). The web-oriented template sections below are adapted accordingly.

**Replaces:** The left SessionPanel (removed, D-02), the aspirational footer hints, and the Phase 9 deferred live clock (D-14 reverses 09-CONTEXT D-29).
**Extends:** 09-UI-SPEC.md §3 SessionPicker overlay, §4 keyboard nav, §5 StatsPanel layout, §6 design tokens — in terminal terms.

---

## 1. Design Philosophy & Principles

Carried forward from 09-UI-SPEC §1 (terminal-first, content-maximal, keyboard-first, minimal chrome, streaming-native, no component library) plus these phase-specific principles:

| Principle | Implication |
|-----------|-------------|
| **Conversation is the product** | The conversation panel owns the screen. The right panel is a passive companion (date/time/session), never a competing work surface. |
| **Session management is summon–choose–exit** | `/session` is an fzf-class overlay: summoned, choose, exit. It is full-screen (D-06), switch-only (D-09), and completely replaces the app tree while open (true key trap). |
| **Honest discoverability** | Footer hints list only real commands (`/session`, `/new`). The aspirational `[/] search` and `[1-3] jump` hints (no handlers exist) are removed. |
| **Modal focus is visually distinct** | App panels use the established green/gray focus border. The modal overlay uses the `$accent` blue border — blue appears nowhere else. |
| **No chrome on every row** | Active-session marker (`●`) appears on exactly one picker row. No glyphs on every row. One border between terminal edge and content — no outer frames. |
| **Redraw on events, contain the clock** | The 1 Hz clock tick lives inside the DatePanel component so re-renders never cascade to the streaming conversation (research Pitfall 3). |

## 2. Design System

| Property | Value |
|----------|-------|
| Tool | none — Ink primitives (`Box`, `Text`) only |
| Component library | none (no shadcn — terminal UI; 09-UI-SPEC §2 "Registry safety") |
| Icon library | none — Unicode glyphs from 09-UI-SPEC §6 (`>`, `●`, `○`, `›`, `▸`, `▊`, `✓`, `✗`, `⚠`, `⠋`) |
| Font | terminal-controlled monospace; **size is not controllable** — hierarchy via weight/color only |
| Styling mechanism | Ink props only (`color`, `backgroundColor`, `dimColor`, `bold`, `italic`, `underline`, `borderStyle`, `borderColor`). No CSS. |
| Design token file | `tui-ink/src/theme.ts` does **not** exist today (colors are inline props per component). New components (DatePanel, SessionPicker) MUST define their colors as named constants at the top of the component file — no raw literals inline in JSX. Existing components are not refactored in this phase. |

## 3. Spacing Scale

**Terminal grid units (1 unit = 1 character cell).** Multiples-of-4 px do not apply in a terminal; the scale below is the cell-equivalent. 0/1/2 cells are the only values used.

| Token | Cells | Usage |
|-------|-------|-------|
| `gap-0` | 0 | Inter-message gap (compact conversation, unchanged) |
| `gap-1` | 1 | Panel padding X, blank row between panel blocks, gap between hint items |
| `gap-2` | 2 | Metadata column separator in picker rows, picker row prefix (cursor + active marker) |
| `panel-width-date` | 28 | DatePanel fixed width (locked band D-05: 24–30; **28 chosen** — fits `YYYY-MM-DD` + `HH:MM:SS` + title with padding, matches research diagram) |
| `panel-width-date-min` | 24 | DatePanel lower bound while rendering (D-05) |
| `picker-row-prefix` | 4 | `> ` (2) + `● ` / `  ` (2) — fixed-width row prefix, keeps alignment |
| `id-column` | 8 | Short session id, `id.slice(0,8)` (D-08) |
| `input-bar-height` | 3 | InputBar incl. border (established) |
| `header-height` | 3 | Header incl. border (established) |
| `min-conversation` | 40 | Conversation min width before DatePanel hides (floor, see §9) |

Exceptions: none — the 09-UI-SPEC scale (`paddingX:1, paddingY:0, marginX:1, marginY:0, toolIndent:2`) is unchanged; Phase 11 only adds the DatePanel width and picker row metrics above.

## 4. Typography

Terminal font, one size, line-height fixed at 1. Declared **weights (exactly 2)** and **attributes (exactly 4: bold, dimColor, italic, underline)**:

| Role | Weight | Attribute | Usage |
|------|--------|-----------|-------|
| Body | regular (default) | — | Message content, date/time values, session titles (non-selected) |
| Emphatic | **bold** | — | Panel titles (with underline), picker cursor row title, time value (`HH:MM:SS` — the hero of the DatePanel), `›` prompt glyph, message role labels (`You`, `▸`) — all established live patterns |
| Muted | regular | `dimColor` | Metadata (ids, message counts, ages, model, hint lines, labels) |
| Subtle | regular | `italic` | Empty states, notices (established) |
| Title | **bold** | `underline` | Panel titles: `Date & Time`, `Switch Session` (matches existing `Sessions` / `Conversation` / `Tool Calls` convention) |

Rules: `italic` is never the only signal (tui-design); `underline` reserved for panel titles only; no `reverse` in the app body — reverse is an allowed but **not required** alternative for the picker cursor (we use `>` + `$accent` instead, per contract_notes).

## 5. Color Contract

Carried forward from 09-UI-SPEC §2, **normalized to the live code vocabulary** (named Ink colors actually in use in `tui-ink/src/`). The only new token is `$accent` (blue), introduced exclusively for the picker.

### 60 / 30 / 10 split

| Token | Ink Value | Live Usage Today | Phase 11 Usage |
|-------|-----------|------------------|----------------|
| `$background` | `#1a1a1a` | App background | unchanged |
| `$surface` | `#222222` | Panel/assistant bg | unchanged |
| `$panel` | `#2a2a2a` | Border/dividers | unchanged |
| `$text` | `white` | Primary content | unchanged |
| `$text-muted` | `dimColor` | Metadata, labels | unchanged |
| `$primary` | `green` | **Success + focus border** (established: `focused ? "green" : "gray"` on all panels), active session `●`, assistant `▸`, input cursor `▊` | **unchanged** — existing focus-border pattern is NOT re-colored |
| `$secondary` | `yellow` | User label `You`, prompt `›`, thinking `●`, truncated marker | unchanged |
| `$error` | `red` | Error messages, `✗` | unchanged + picker error line |
| `$header-accent` | `cyan` | Header border + app name (established exception) | unchanged |
| **`$accent`** | `blue` | — | **NEW — picker only:** cursor `>`, cursor-row title, and the picker's border (modal focus signal) |

### Accent reserved for (explicit — never "all interactive elements")

`$accent` blue is used in **exactly three places**, all inside the `/session` SessionPicker:
1. Picker border (`borderColor="blue"`) — signals modal focus, distinct from app green/gray borders.
2. Cursor prefix `>` (bold blue) on the focused row.
3. Cursor-row session title (bold, blue) — the selected item's emphasis.

Blue is NOT used for: buttons, the DatePanel, header, footer, input bar, or any general interactive element.

### Color rules (tui-design)
- Every color signal is paired with a symbol or weight (CVD-safe): active `●`+green, cursor `>`+blue, error `✗`+red, focus = border color change + `>` cursor. No color-alone signaling.
- Semantic meaning only: green = active/success/focus, yellow = user/processing, red = error, blue = modal selection.

## 6. Component Design Contract

### 6.1 App main layout (app.tsx — modified)

**States:** Connected (normal tree) · Connecting (existing, unchanged) · Connect-error (existing, unchanged) · Picker open (conditional full-screen replacement).

**Structure (Box tree):**
```
<Box flexDirection="column" height="100%">
  <Header />                                        ← kept (D-03), unchanged
  <Box flexGrow={1} flexDirection="row">
    <FocusablePanel id="conversation">              ← conversation panel, flexGrow 1
      {(focused) => <ConversationPanel focused={focused} />}
    </FocusablePanel>
    <DatePanel />                                   ← NEW, right, fixed 28 cols, NOT focusable
  </Box>
  <FocusablePanel id="tool-monitor">                ← kept (D-04), unchanged, renders only when toolCalls exist
    {(focused) => <ToolMonitorPanel focused={focused} />}
  </FocusablePanel>
  <FocusablePanel id="input">
    {(focused) => <InputBar client={client} />}     ← modified: /session + /new branches
  </FocusablePanel>
  <Footer />                                        ← modified: honest hints
</Box>

{/* when pickerOpen: return <SessionPicker client={client} onClose={...} /> INSTEAD of the tree above */}
```

**Contract:**
- `SessionPanel` import, `FocusablePanel id="sessions"` block, and `session-panel.tsx` are **deleted** (D-02).
- DatePanel is **not** wrapped in `FocusablePanel` — it is passive display, no focus stop, border always gray.
- Focus cycle becomes: `conversation ↔ input` (tool-monitor joins only while visible — unchanged Tab behavior otherwise).
- **Key trap:** when `pickerOpen` is true, `App` returns `<SessionPicker>` in place of the entire layout. InputBar unmounts → its `useInput` unregisters. The App-level `q` quit handler must `if (pickerOpen) return` (research Pitfall 2) — `q` inside the picker is handled by the picker (closes it).
- Picker open state is **local `useState` in App** (no store change needed).

### 6.2 DatePanel (new — `tui-ink/src/panels/date-panel.tsx`)

**Purpose:** Passive right companion panel: live date, live time (1 Hz), active session name (D-14/D-15/D-16).

**States:** Always rendered (when terminal width ≥ 68, see §9). No interaction states — display only.

**Behavior:**
- `useState<Date>(new Date())` + `useEffect(() => { const t = setInterval(() => setNow(new Date()), 1000); return () => clearInterval(t) }, [])` — **Ink ^7.1.0 has no `useInterval`** (research-verified); this is the only ticker.
- Reads session via the existing header selector pattern: `const { sessions, activeSessionId } = useAgentStore(); const active = sessions.find((s) => s.id === activeSessionId)`.
- Renders on every tick; subscription is component-local (research Pitfall 3).

**Visual spec:**
- `width={28}`, `borderStyle="single"`, `borderColor="gray"` (never focused — passive), `paddingX={1}`, `flexDirection="column"`.
- Row 1: `<Text bold underline>Date & Time</Text>` (matches panel-title convention).
- One blank row. Then content column:
  - Date line: `<Text>{dateStr}</Text>` — format **ISO `YYYY-MM-DD`** (chosen from discretion; fixed-width, sortable, terminal-idiomatic; the "Jul 31, 2026" alternative was considered and rejected).
  - Time line: `<Text bold>{timeStr}</Text>` — **24h `HH:MM:SS`**, zero-padded (D-15), the visual hero.
  - One blank row.
  - `<Text dimColor>Session</Text>` label line.
  - `<Text>{sessionTitle}</Text>` — `active?.title ?? "untitled"`, truncated to panel content width (24 cells) with `…`.
- No other content (D-16 locks exactly date + time + session name).

### 6.3 SessionPicker overlay (new — `tui-ink/src/components/session-picker.tsx`)

**Purpose:** Full-screen, switch-only session selector (D-06, D-09). Opened by typing `/session` + Enter in the input bar.

**States:**

| State | Visual |
|-------|--------|
| Loading | `Loading sessions...` — dim |
| List | Rows sorted **`updated_at` desc** (D-08 "most-recent first"; research Pitfall 5) |
| Empty | `No sessions yet. Press Esc and type /new to start one.` — dim, italic, centered |
| Load error | `Could not load sessions — press Esc to close.` — red |
| Switching (Enter pressed) | Keys disabled; dim status line `Loading session…`; on success close, on failure stay open with red `Failed to load session: {message}` |

**Behavior (interaction contract):**
1. On mount: `client.listSessions()` → seed local `rows` (sorted `updated_at` desc) AND `useAgentStore.getState().setSessions(rows)` (keeps header/DatePanel in sync).
2. `↑`/`↓` move cursor; **clamp at list ends, no wrap** (standard picker behavior).
3. `Enter` on a row: (a) disable keys + show `Loading session…`; (b) `client.switchSession(id)` → if `false`, show `Failed to switch session` red and stay open; (c) `client.getSessionHistory(id)` (new `sessions.get` RPC); (d) `store.setActiveSession(id)`, `store.loadConversation(mappedHistory)`, `store.setSessions(rows)`; (e) `onClose()`.
4. `Esc` **and** `q` close the picker, returning to the app with all state preserved (matches 09-UI-SPEC §4; research Pitfall 2).
5. Row list scrolls as a **window**: visible row count = available height; when the cursor moves beyond the window edge, scroll by one row so the cursor stays visible.

**Row contract (D-08 + 09-UI-SPEC §3, in cells):**
```
[prefix 4]  [title flex, truncated "…"]        [id 8]  [N msgs]  [age]
> ● weather-tok                            abc12345  12 msgs  2h ago
    code-review                            def67890   8 msgs  1d ago
```
- Prefix (fixed 4 cells): `> ` (bold blue, cursor row) or `  `; then `● ` (green, **only on the active session row** — color+symbol pair) or `  `. Cursor on active row renders `> ● `. **No glyph on 100% of rows** (clutter audit).
- Title: `(s.title ?? "untitled")`, tail-truncated with `…` to remaining width; **bold + `$accent` blue on the cursor row**, `$text` otherwise.
- Metadata block (right-aligned via `flexGrow` spacer, all `dimColor`, items separated by 2 cells): `s.id.slice(0,8)` · `{message_count} msgs` · relative age.
- Relative age (research Pattern 2): `<60s → "just now"`; `<3600s → "{Math.round(s/60)}m ago"`; `<86400s → "{Math.round(s/3600)}h ago"`; else `"{Math.round(s/86400)}d ago"`; computed from `updated_at`.

**Visual spec (full-screen frame):**
- `flexDirection="column" height="100%" width="100%"`, `borderStyle="single"`, `borderColor="blue"` (**$accent — the modal focus signal**), `paddingX={1}`.
- Title row: `<Text bold underline>Switch Session</Text>`.
- One blank row; rows column (`flexGrow={1}`); one blank row.
- Bottom hint line (dim): `↑ ↓ navigate  •  Enter select  •  Esc/q close` (exact 09-UI-SPEC §3 phrasing).

### 6.4 InputBar command handling (app.tsx — extended)

Existing slash-command interception at `app.tsx:36-48` gains two branches (research Pattern 1):

| Input (trimmed) | Action |
|-----------------|--------|
| `/session` | `setPickerOpen(true)` — the picker renders next frame; input cleared |
| `/new` | `client.createSession()` → `store.setActiveSession(newId)` → `store.resetConversation()` → input cleared. **Immediate, no confirm** (D-11; session auto-saved via JSONL, D-12/D-13 backend-side) |
| `/sessions` | existing behavior (kept) |
| anything else | `client.submitPrompt(trimmed)` — unchanged |

### 6.5 Footer hints (footer.tsx — modified)

Replace the hint set (research open-question 5 recommendation). Remove aspirational `[/] search` and `[1-3] jump`. Exact new hint set (dim, `[`-wrapped, single-space separated):

```
[?] help  [/session] sessions  [/new] new chat  [Tab] panels  [q] quit
```

### 6.6 ConversationPanel (unchanged)

Kept exactly as-is except: it becomes the sole content panel (SessionPanel removed) and its title/border/focus behavior is untouched. Empty state remains `Type a message to start a conversation` (dim, italic) — this is what the user sees after `/new` (D-11/D-12) until the first prompt.

## 7. Interaction Contract

### Keyboard & input

| Key | Context | Action |
|-----|---------|--------|
| `Enter` | Input bar, text = `/session` | Open SessionPicker overlay (D-06) |
| `Enter` | Input bar, text = `/new` | Create + switch + reset conversation, no confirm (D-11/D-12) |
| `Enter` | Input bar, other text | `submitPrompt` (unchanged) |
| `↑` / `↓` | Input bar | Input history (unchanged) |
| `↑` / `↓` | Picker open | Move cursor, clamp at ends |
| `Enter` | Picker open | Select row → switch + load history + close (D-07/D-10) |
| `Esc` / `q` | Picker open | Close picker, preserve app state (09-UI-SPEC §4) |
| `Esc` | ErrorBar visible | Dismiss (unchanged) |
| `q` | App (picker closed) | Quit (unchanged) |
| `q` | App (picker open) | **ignored at App level** — picker owns it (research Pitfall 2) |
| `Tab` | App | Focus cycle: conversation ↔ input (tool-monitor when visible); DatePanel skipped |

### Navigation table

| Transition | Trigger | Behavior |
|------------|---------|----------|
| App → picker | `/session` + Enter | Full-screen overlay; InputBar unmounts; only picker's `useInput` active (key trap) |
| Picker → App (cancel) | `Esc` / `q` | State fully preserved (conversation, input text) |
| Picker → App (switch) | `Enter` on row | Session switched, history loaded into conversation, picker closes |
| App → fresh chat | `/new` + Enter | New session active, conversation cleared, header/DatePanel title update |

### Feedback & loading

| Scenario | Indicator |
|----------|-----------|
| Picker opening | `Loading sessions...` dim until `sessions.list` resolves |
| Session switch in progress | `Loading session…` dim, keys disabled |
| Switch/history failure | Red `Failed to load session: {message}`, picker stays open |
| `/new` executed | Conversation empty state (existing copy); header + DatePanel show `untitled` until first prompt auto-titles (D-13) |
| Clock tick | DatePanel time line updates 1 Hz; nothing else re-renders |

## 9. Floor Pressure-Test (tui-design)

| Terminal width | Behavior |
|----------------|----------|
| ≥ 68 cols | Full layout: conversation (≥40) + DatePanel 28 (40 + 28 = 68 floor). Conversation title/id truncation handles narrow rows. |
| < 68 cols | **DatePanel hidden**; conversation takes full width (single-pane fallback; a 60-col tmux split stays usable). Picker unaffected (full-screen). |
| < 50 cols | Picker rows degrade via title `…` truncation only; no layout break. |

Rule: `DatePanel` renders `if (width >= 68)` (use `useWindowSize` from Ink). No "terminal too small" screen is needed this phase — nothing below collapses structurally.
