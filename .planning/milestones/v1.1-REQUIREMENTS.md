## v1.1 Requirements (Skills System)

### Skill Storage & Format

- [x] **STORE-01**: User can author a skill as a `SKILL.md` file at `.agentharness/skills/<name>/SKILL.md` (one folder per skill)
  - **Outcome:** Validated — Phase 12 (frontmatter parser + folder-per-skill discovery)
- [x] **STORE-02**: Skill name is kebab-case and matches the folder name
  - **Outcome:** Validated — Phase 12 (name validation; win32 case-insensitive match)
- [x] **STORE-03**: User can provide `name` and `description` frontmatter (required) and `allowed-tools` (optional)
  - **Outcome:** Validated — Phase 12 (`allowed-tools` parsed + shape-validated, enforcement deferred)
- [x] **STORE-04**: Skills with missing/invalid frontmatter are skipped with a warning and never break the harness
  - **Outcome:** Validated — Phase 12 (skip-and-warn taxonomy)
- [x] **STORE-05**: Duplicate skill names resolve deterministically (first-wins) with a warning about the shadowed skill
  - **Outcome:** Validated — Phase 12 (deterministic first-wins scan)

### Progressive Disclosure

- [x] **DISC-01**: Agent sees a manifest of every skill's `name` + `description` in the system prompt each turn
  - **Outcome:** Validated — Phase 12/12-04 (seam appended at end of `_build_system_prompt()`, D-12)
- [x] **DISC-02**: Manifest is subject to a budget (character/token cap) with trimming of over-long skills
  - **Outcome:** Validated — Phase 12 (`manifest_max_chars`, default ~1,500, longest-first trim)
- [x] **DISC-03**: Agent can load a skill body on demand via a dedicated `read_skill` tool when the description matches the current task
  - **Outcome:** Validated — Phase 14 (`__skills__` provider, single shared `load_skill()` path)
- [x] **DISC-04**: `read_skill` reads are path-scoped to the skills directory — no traversal outside it
  - **Outcome:** Validated — Phase 14 (canonicalize+contain guard, win32 test vectors)
- [x] **DISC-05**: Skills support bundled resources (`references/`, `scripts/`, `assets/`) readable on demand through path-scoped reads into the skill directory
  - **Outcome:** Validated — Phase 14 (`read_skill_path`, Level-3 disclosure)

### Activation & Session Behavior

- [x] **ACT-01**: User can force-load a skill via a `/skill <name>` slash command
  - **Outcome:** Validated — Phase 15 (4-layer RPC + REPL branch) and Phase 16 (TUI intercept)
- [x] **ACT-02**: Agent auto-invokes skills when a manifest description matches the current task
  - **Outcome:** Validated — Phase 14 (exactly-once dedup, H-01 closed)
- [x] **ACT-03**: Loaded skill body persists for the rest of the session as a system-role message
  - **Outcome:** Validated — Phase 13 (`Message.persist` + non-serialized `skill_state`)
- [x] **ACT-04**: Loaded skill bodies survive context summarization (system-role exemption)
  - **Outcome:** Validated — Phase 13 (documented exemption at `context.py:88`, test-proven)
- [x] **ACT-05**: Loaded skills are session-scoped — never persisted to the JSONL session file
  - **Outcome:** Validated — Phase 13 (`to_events()` persist filter + `mark_saved()` index fix)
- [x] **ACT-06**: TUI shows a visible indicator when a skill is loaded
  - **Outcome:** Validated — Phase 16 (footer chip + notice tones via typed `skill_loaded` notification)

### Skill Capabilities

- [x] **CAP-01**: Skill bodies are markdown instructions that can reference bundled files relative to the skill directory
  - **Outcome:** Validated — Phase 14 (path-scoped `read_skill_path`)
- [ ] **CAP-02**: A skill's optional `allowed-tools` filters the tool list passed to the LLM while the skill is loaded
  - **Outcome:** **DEFERRED** — Phase 17 cancelled (2026-08-04). Pure contract `retain_read_skills()`/`intersect_allowed_tools()` shipped + unit-tested, un-wired. Future/end milestone.
- [x] **CAP-03**: `read_skill` is always retained in the tool list even when `allowed-tools` filtering is active
  - **Outcome:** Validated as contract — Phase 14 (retention contract unit-tested; enforcement deferred with CAP-02)
- [ ] **CAP-04**: When multiple skills with `allowed-tools` are loaded, filtering uses documented intersection semantics
  - **Outcome:** **DEFERRED** — semantics decided + unit-tested (Phase 15, `docs/skills-allowed-tools.md`), enforcement deferred. Phase 17 cancelled. Future/end milestone.

## v1.2 Requirements (Future — not part of v1.1)

### Skill Authoring & Management

- **AUTH-01**: User can create, list, and edit skills from the harness (management tools)
- **AUTH-02**: TUI shows a `/skills` listing command

### Expanded Skills

- **EXPD-01**: Skills bundle scripts that register as first-class harness tools (script-as-tool)
- **EXPD-02**: Skills live in a user-global directory (~/.config/agentharness/skills/) for cross-project reuse
- **EXPD-03**: Skill chaining / nested skills
- **EXPD-04**: Skill marketplace / sharing / plugin-provided skills

## Out of Scope

| Feature | Reason |
|---------|--------|
| Keyword/algorithmic skill matching | Progressive disclosure uses pure LLM reasoning over descriptions (D-06, ecosystem standard) |
| Script-as-tool registration | D-15 defers — skills are markdown instructions + bundled files in v1.1 |
| Persisting loaded skill bodies to JSONL | D-13 — loaded skills are session-scoped |
| Loading all skill bodies at startup | Defeats progressive disclosure entirely |
| Skill authoring UI / management tools | Deferred to v1.2 |
| User-global skills directory | Deferred to v1.2 (D-01: project-local only) |
| Manifest with no cap | Unbounded system-prompt growth as skills accumulate |
