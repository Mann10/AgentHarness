# Milestone v1.1: Skills System

**Status:** ✅ SHIPPED 2026-08-04
**Phases:** 12-17 (Phase 17 CANCELLED)
**Total Plans:** 20 executed

## Overview

Progressive-disclosure skills for AgentHarness — users author `SKILL.md` files under `.agentharness/skills/`, the agent sees a cheap budgeted manifest (name + description) in the system prompt each turn, and the full skill body loads into context only on demand (via `read_skill` or `/skill`). Six phases, dependency-ordered pure → integrated, with the highest-risk change (session serialization) placed second so the JSONL exclusion is proven before any real skill body flows. Phase 17 (allowed-tools enforcement) was cancelled by user decision — the pure filter contracts shipped in Phase 15 remain un-wired, and CAP-02/CAP-04 are deferred to a future/end milestone.

**Plans**: 3 plans

**Details:**
- Requirements: ACT-03, ACT-04, ACT-05

## Milestone Summary

**Decimal Phases:**

- None — all v1.1 phases were integer-numbered (12-17). Phase 17 cancelled rather than split.

**Key Decisions:**

- Decision: Project-local skills dir `.agentharness/skills/` (Rationale: co-located with session/queue data, versioned in repo; D-01)
- Decision: Manifest (name + description) in system prompt, budgeted ~1,500 chars, longest-first trim (Rationale: progressive disclosure Level 1, D-06/D-07)
- Decision: `read_skill` reserved un-namespaced `__skills__` tool, path-scoped reads with canonicalize+contain traversal guard (Rationale: Level 2/3 disclosure, D-08/D-10)
- Decision: Loaded bodies persist as system-role messages, never to JSONL (Rationale: session-scoped, summarization-exempt by construction; D-12/D-13)
- Decision: `LOADED_SKILL_TOKEN_CAP` (default 8000) separate accounting (Rationale: keeps summarization threshold chat-relative)
- Decision: CAP-04 intersection semantics locked in Phase 15, enforcement deferred (Rationale: contract-before-enforcement; Phase 17 implements only)
